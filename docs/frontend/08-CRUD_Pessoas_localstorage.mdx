
# 📘 CRUD de Pessoas Físicas e Jurídicas com Armazenamento Local

## Parte 1 — Evolução da aplicação, navegação e organização das rotas

No capítulo anterior, desenvolvemos uma aplicação React para o cadastro de **Pessoas Físicas (PF)** e **Pessoas Jurídicas (PJ)**, utilizando conceitos de Programação Orientada a Objetos, componentes React, Ant Design e persistência de dados por meio do `localStorage`.

Até esse momento, nossa aplicação permite cadastrar pessoas e armazenar suas informações localmente no navegador.

Entretanto, um sistema de cadastro normalmente precisa oferecer outras funcionalidades, como consultar registros existentes, visualizar informações, atualizar dados e excluir cadastros.

Neste capítulo, ampliaremos a aplicação para implementar as operações de um **CRUD completo**.

A sigla CRUD representa quatro operações fundamentais:

| Operação | Significado | Funcionalidade |
|---|---|---|
| **Create** | Criar | Cadastrar uma nova pessoa |
| **Read** | Ler | Listar e consultar pessoas cadastradas |
| **Update** | Atualizar | Modificar informações de um cadastro |
| **Delete** | Excluir | Remover um registro existente |

Nosso objetivo é construir essas funcionalidades reutilizando os componentes e as classes desenvolvidos anteriormente.

Ao final do capítulo, teremos uma aplicação que permitirá:

- Cadastrar pessoas físicas e jurídicas;
- Listar os registros armazenados;
- Filtrar pessoas pelo nome;
- Visualizar os detalhes de um cadastro;
- Editar informações existentes;
- Excluir registros mediante confirmação;
- Navegar entre as funcionalidades sem recarregar a página.

:::info Continuidade do projeto

Este capítulo é uma evolução direta do projeto desenvolvido anteriormente.

Não será necessário criar uma nova aplicação React. Trabalharemos sobre a estrutura existente, reaproveitando as classes de domínio e os componentes já implementados.

:::

# 2. Introdução à navegação em aplicações React

Até o momento, nossa aplicação apresenta diretamente o formulário de cadastro.

Essa abordagem funciona bem quando existe apenas uma tela.

Entretanto, com a implementação do CRUD, precisaremos navegar entre diferentes funcionalidades.

Por exemplo:

```text
Cadastro de Pessoas
       │
       ▼
Listagem de Pessoas
       │
       ├── Visualizar Pessoa
       │
       ├── Editar Pessoa
       │
       └── Excluir Pessoa
```

Para organizar essa navegação, utilizaremos o **React Router DOM**.

## 2.1. O que é React Router DOM?

O React Router DOM é uma biblioteca que permite implementar navegação entre diferentes componentes React utilizando URLs.

Com essa biblioteca, podemos associar cada endereço da aplicação a um componente específico.

Por exemplo:

| URL | Funcionalidade |
|---|---|
| `/cadastrar` | Formulário de cadastro |
| `/listar` | Listagem de pessoas |
| `/visualizar/PF/123` | Visualização de uma Pessoa Física |
| `/editar/PJ/456` | Edição de uma Pessoa Jurídica |

Quando o usuário acessa uma dessas URLs, o React Router identifica qual componente deve ser apresentado.

Essa abordagem é muito utilizada em aplicações do tipo **SPA (Single Page Application)**.

## 2.2. O conceito de SPA

Uma SPA é uma aplicação web que atualiza o conteúdo apresentado ao usuário sem precisar recarregar completamente a página a cada navegação.

Em uma aplicação tradicional, a mudança de página normalmente envolve uma nova requisição para carregar outro documento HTML.

Em uma SPA, o JavaScript controla a interface e substitui os componentes apresentados conforme a navegação.

Podemos representar esse funcionamento da seguinte maneira:

```text
Navegador
    │
    ▼
Aplicação React
    │
    ▼
React Router
    │
    ├── /cadastrar
    │      └── PessoaFormOO
    │
    ├── /listar
    │      └── ListaPessoas
    │
    ├── /visualizar/:tipo/:id
    │      └── VisualizaPessoa
    │
    └── /editar/:tipo/:id
           └── PessoaFormOO
```

Observe que utilizaremos o mesmo componente `PessoaFormOO` para duas funcionalidades diferentes: cadastro e edição.

Essa reutilização será possível porque o componente poderá identificar, por meio da URL, se está criando um novo registro ou editando um cadastro existente.

## 2.3. Instalando o React Router DOM

Para utilizar a biblioteca, execute no terminal do projeto:

```bash
npm install react-router-dom
```

Após a instalação, poderemos importar os recursos necessários:

```jsx
import {
  BrowserRouter,
  Routes,
  Route,
  Navigate,
  Link,
  Outlet,
  useLocation,
  useNavigate,
  useParams
} from "react-router-dom";
```

Os principais recursos são:

| Recurso | Finalidade |
|---|---|
| `BrowserRouter` | Gerenciar o histórico de navegação |
| `Routes` | Agrupar as rotas da aplicação |
| `Route` | Associar uma URL a um componente |
| `Navigate` | Redirecionar para outra rota |
| `Link` | Criar links de navegação |
| `Outlet` | Indicar onde as rotas filhas serão apresentadas |
| `useLocation` | Identificar a URL atual |
| `useNavigate` | Navegar programaticamente |
| `useParams` | Recuperar parâmetros presentes na URL |

# 3. Construindo o layout da aplicação

Com a introdução de diferentes telas, precisamos organizar a interface de maneira que o usuário consiga navegar entre as funcionalidades.

Para isso, construiremos um componente chamado `MainLayout`.

Esse componente será responsável por apresentar:

- Cabeçalho da aplicação;
- Menu de navegação;
- Área principal de conteúdo;
- Rodapé;
- Menu adaptado para dispositivos móveis.

A estrutura visual será:

```text
+--------------------------------------+
|           CABEÇALHO                  |
|       Sistema de Cadastro            |
|                                      |
|       Cadastrar       Listar         |
+--------------------------------------+
|                                      |
|                                      |
|         CONTEÚDO DA ROTA             |
|                                      |
|                                      |
+--------------------------------------+
|               RODAPÉ                 |
+--------------------------------------+
```

O conteúdo central será alterado conforme a rota selecionada, enquanto o cabeçalho e o rodapé permanecerão disponíveis.

## 3.1. Arquivo `MainLayout.jsx` — NOVO

Crie o diretório:

```text
src/layout/
```

Dentro dele, crie o arquivo:

```text
MainLayout.jsx
```

A seguir, apresentamos o código completo.

```jsx title="src/layout/MainLayout.jsx"
import React, { useState, useEffect } from "react";
import { Outlet, Link, useLocation } from "react-router-dom";
import { Layout, Menu, Drawer, Button } from "antd";

import {
  UserAddOutlined,
  UnorderedListOutlined,
  MenuOutlined,
} from "@ant-design/icons";

const { Header, Content, Footer } = Layout;

function MainLayout() {

  const location = useLocation();

  const [isMobile, setIsMobile] = useState(false);
  const [drawerVisible, setDrawerVisible] = useState(false);

  // Detecta tamanho da tela
  useEffect(() => {

    function handleResize() {
      setIsMobile(window.innerWidth < 768);
    }

    handleResize();

    window.addEventListener("resize", handleResize);

    return () =>
      window.removeEventListener("resize", handleResize);

  }, []);

  const currentKey =
    location.pathname.startsWith("/listar") ||
    location.pathname.startsWith("/visualizar")
      ? "/listar"
      : "/cadastrar";

  const menuItems = [
    {
      key: "/cadastrar",
      icon: <UserAddOutlined />,
      label: <Link to="/cadastrar">Cadastrar</Link>,
    },
    {
      key: "/listar",
      icon: <UnorderedListOutlined />,
      label: <Link to="/listar">Listar</Link>,
    },
  ];

  return (
    <Layout
      style={{
        minHeight: "100vh",
        background: "#f7f7f7"
      }}
    >

      {/* ===== Cabeçalho ===== */}

      <Header
        style={{
          position: "sticky",
          top: 0,
          zIndex: 1000,
          width: "100%",
          background: "#fff",
          boxShadow: "0 2px 8px rgba(0,0,0,0.1)",
          display: "flex",
          alignItems: "center",
          justifyContent: "space-between",
          paddingInline: 16,
        }}
      >

        {/* Logo / Título */}

        <div
          style={{
            fontSize: "1.2rem",
            fontWeight: "600",
            color: "#333",
          }}
        >
          Sistema de Cadastro
        </div>

        {/* Menu Desktop */}

        {!isMobile && (
          <Menu
            mode="horizontal"
            selectedKeys={[currentKey]}
            items={menuItems}
            style={{
              background: "transparent",
              borderBottom: "none",
              fontWeight: 500,
              flex: 1,
              justifyContent: "flex-end",
            }}
          />
        )}

        {/* Botão Mobile */}

        {isMobile && (
          <Button
            type="text"
            icon={
              <MenuOutlined
                style={{ fontSize: 22 }}
              />
            }
            onClick={() => setDrawerVisible(true)}
          />
        )}

      </Header>

      {/* ===== Menu lateral mobile ===== */}

      <Drawer
        title="Menu"
        placement="right"
        onClose={() => setDrawerVisible(false)}
        open={drawerVisible}
        bodyStyle={{ padding: 0 }}
      >

        <Menu
          mode="inline"
          selectedKeys={[currentKey]}
          items={menuItems}
          onClick={() => setDrawerVisible(false)}
        />

      </Drawer>

      {/* ===== Conteúdo principal ===== */}

      <Content
        style={{
          padding: "24px",
          background: "#ffffff",
          margin: "24px",
          borderRadius: "8px",
          boxShadow: "0 1px 4px rgba(0,0,0,0.08)",
        }}
      >

        <Outlet />

      </Content>

      {/* ===== Rodapé ===== */}

      <Footer
        style={{
          textAlign: "center",
          background: "#f7f7f7",
          color: "#555",
        }}
      >
        Sistema de Cadastro de Pessoas ©2025
      </Footer>

    </Layout>
  );
}

export default MainLayout;
```

## 3.2. Entendendo o componente MainLayout

O componente utiliza recursos que já estudamos anteriormente, como `useState`, `useEffect` e composição de componentes.

Entretanto, introduz alguns elementos específicos da navegação.

### O componente Outlet

Observe o trecho:

```jsx
<Outlet />
```

O `Outlet` representa a área em que o React Router apresentará o componente associado à rota selecionada.

Por exemplo, quando o usuário acessar `/listar`, o componente `ListaPessoas` será renderizado no local ocupado pelo `Outlet`.

Dessa forma, não precisamos repetir o cabeçalho e o rodapé em todas as páginas.

### O hook useLocation

O hook `useLocation()` permite identificar a URL atual.

```jsx
const location = useLocation();
```

Essa informação é utilizada para destacar o item correspondente no menu de navegação.

Por exemplo:

```jsx
const currentKey =
  location.pathname.startsWith("/listar") ||
  location.pathname.startsWith("/visualizar")
    ? "/listar"
    : "/cadastrar";
```

Quando o usuário estiver na listagem ou na visualização de um cadastro, o menu destacará a opção **Listar**.

Nas demais situações, será destacada a opção **Cadastrar**.

### Layout responsivo

O componente também utiliza o hook `useEffect()` para identificar alterações no tamanho da janela.

```jsx
useEffect(() => {

  function handleResize() {
    setIsMobile(window.innerWidth < 768);
  }

  handleResize();

  window.addEventListener("resize", handleResize);

  return () =>
    window.removeEventListener("resize", handleResize);

}, []);
```

Quando a largura da janela for inferior a 768 pixels, o menu horizontal será substituído por um botão que permite abrir um menu lateral.

Esse menu utiliza o componente `Drawer`, disponibilizado pelo Ant Design.

:::tip Reutilização de componentes

O `MainLayout` será compartilhado por todas as telas da aplicação.

Essa abordagem evita duplicação de código e facilita futuras alterações na aparência do sistema.

:::

```jsx title="src/routes/AppRoutes.jsx"
import MainLayout from "../layout/MainLayout.jsx";

          element={

          path="cadastrar"

          path="listar"

          path="visualizar/:tipo/:id"
```

## 4.2. Entendendo a definição das rotas

O componente `Routes` agrupa as rotas da aplicação:

```jsx
<Routes>
  ...
</Routes>
```

Cada componente `Route` associa um caminho a um componente React.

Por exemplo:

```jsx
<Route
  path="listar"
  element={<ListaPessoas />}
/>
```

Essa declaração indica que, ao acessar `/listar`, o React Router deverá apresentar o componente `ListaPessoas`.

### Rotas aninhadas

Observe a declaração:

```jsx
<Route
  path="/"
  element={<MainLayout />}
>
```

As demais rotas foram declaradas dentro dessa rota principal.

Isso significa que os componentes associados às rotas filhas serão apresentados dentro do `MainLayout`.

O conteúdo de cada rota será renderizado no local definido pelo componente `Outlet`.

### Redirecionamento

A declaração:

```jsx
<Route
  index
  element={
    <Navigate to="cadastrar" replace />
  }
/>
```

indica que, ao acessar a URL inicial `/`, o usuário será redirecionado automaticamente para `/cadastrar`.

### Rotas com parâmetros

Observe a rota:

```jsx
<Route
  path="editar/:tipo/:id"
  element={<PessoaForm />}
/>
```

Os segmentos `:tipo` e `:id` representam parâmetros dinâmicos.

Por exemplo:

```text
/editar/PF/123
```

Nesse endereço:

- `PF` identifica o tipo de pessoa;
- `123` representa o identificador do cadastro.

Posteriormente, utilizaremos o hook `useParams()` para recuperar essas informações e carregar os dados correspondentes.

:::info Cadastro e edição com o mesmo componente

Observe que as rotas `/cadastrar` e `/editar/:tipo/:id` utilizam o mesmo componente:

```jsx
<PessoaForm />
```

Isso será possível porque o formulário identificará se existe um registro a ser editado.

Caso não existam parâmetros de edição, o formulário será utilizado para cadastrar uma nova pessoa.

Caso os parâmetros estejam presentes, o componente poderá recuperar os dados existentes e permitir sua atualização.

Essa funcionalidade será implementada em uma das próximas partes.

:::

# 5. Como os componentes trabalharão em conjunto

Após a conclusão do capítulo, a navegação seguirá a seguinte estrutura:

```text
App.jsx
   │
   ▼

   │

   │
```

- O `App.jsx` inicializa a navegação.

- O `MainLayout.jsx` organiza a interface visual.
- Os componentes de cadastro, listagem e visualização implementam as funcionalidades específicas.
- Os DAOs realizam as operações de persistência no `localStorage`.

Essa separação facilita a manutenção e a evolução do projeto.

## 1. Evolução das operações de persistência

No capítulo anterior, estudamos a utilização do `localStorage` para armazenar objetos.

Entretanto, para implementar um CRUD completo, precisamos estabelecer uma maneira de identificar cada registro armazenado.

Considere a seguinte situação:

Uma aplicação possui três pessoas físicas cadastradas.

```json
[
  {
    "nome": "Ana Silva",
    "cpf": "11111111111"
  },
  {
    "nome": "Carlos Souza",
    "cpf": "22222222222"
  },
  {
    "nome": "Mariana Costa",
    "cpf": "33333333333"
  }
]
```

Se precisarmos alterar o cadastro de Carlos, como identificaremos exatamente qual objeto deverá ser atualizado?

Uma possibilidade seria utilizar o CPF.

Entretanto, em sistemas de informação, é comum utilizar um **identificador próprio para cada registro**, independente dos demais atributos.

Assim, nossos objetos passarão a possuir uma propriedade chamada `id`.

```json
[
  {
    "id": "abc123",
    "nome": "Ana Silva",
    "cpf": "11111111111"
  },
  {
    "id": "def456",
    "nome": "Carlos Souza",
    "cpf": "22222222222"
  },
  {
    "id": "ghi789",
    "nome": "Mariana Costa",
    "cpf": "33333333333"
  }
]
```

Agora, para atualizar Carlos, basta localizar o objeto cujo `id` seja igual a `"def456"`.

Essa mesma identificação será utilizada posteriormente nas rotas da aplicação.

Por exemplo:

```text
/visualizar/PF/def456
/editar/PF/def456
```

:::tip Identificadores e persistência

O identificador `id` representa a identidade de um registro dentro do sistema.

Ele não substitui documentos como CPF e CNPJ, que continuam sendo atributos específicos das pessoas cadastradas.

:::

## 2. Organização das operações CRUD

## 3. Evoluindo o DAO de Pessoa Física

**Arquivo: `src/objetos/dao/PFDAOLocal.mjs` — MODIFICADO**

O DAO de Pessoa Física continuará utilizando a chave `pessoasFisicas` no `localStorage`.

Essa chave é importante porque permite que os dados permaneçam armazenados no mesmo local utilizado anteriormente.

A principal evolução consiste em incorporar um identificador para cada novo registro e disponibilizar métodos para atualização e exclusão.

### 3.1. Código completo do arquivo

Substitua integralmente o conteúdo do arquivo `PFDAOLocal.mjs` pelo código abaixo.

```javascript title="src/objetos/dao/PFDAOLocal.mjs"
export default class PFDAO {

  constructor() {
    this.chave = "pessoasFisicas";
  }

  // Recupera os registros armazenados
  listar() {
    try {
      const dados = localStorage.getItem(this.chave);

      return dados ? JSON.parse(dados) : [];

    } catch (e) {
      console.error("Erro ao ler PF:", e);
      return [];
    }
  }

  // Gera um identificador para o registro
  gerarId() {
    return (
      Date.now().toString(36) +
      Math.random().toString(36).substring(2, 9)
    );
  }

  // Converte a instância de PF em objeto simples
  toPlain(pf) {

    if (!pf) return {};

    const end = pf.getEndereco?.();
    const titulo = pf.getTitulo?.();
    const telefones = pf.getTelefones?.() || [];

    return {
      id: pf.id ?? this.gerarId(),

      nome: pf.getNome?.(),
      email: pf.getEmail?.(),
      cpf: pf.getCPF?.(),

      endereco: end
        ? {
            cep: end.getCep?.(),
            logradouro: end.getLogradouro?.(),
            bairro: end.getBairro?.(),
            cidade: end.getCidade?.(),
            uf: end.getUf?.(),
            regiao: end.getRegiao?.(),
          }
        : {},

      telefones: telefones.map((t) => ({
        ddd: t.getDdd?.(),
        numero: t.getNumero?.(),
      })),

      titulo: titulo
        ? {
            numero: titulo.getNumero?.(),
            zona: titulo.getZona?.(),
            secao: titulo.getSecao?.(),
          }
        : {},
    };
  }

  // CREATE: cadastra uma pessoa física
  salvar(pf) {

    const lista = this.listar();
    const obj = this.toPlain(pf);

    if (!obj.id) {
      obj.id = this.gerarId();
    }

    lista.push(obj);

    localStorage.setItem(
      this.chave,
      JSON.stringify(lista)
    );

    return obj;
  }

  // UPDATE: atualiza uma pessoa física
  atualizar(id, novoPF) {

    const lista = this.listar();
    const obj = this.toPlain(novoPF);

    obj.id = id;

    const idx = lista.findIndex(
      (p) => p.id === id
    );

    if (idx >= 0) {
      lista[idx] = obj;
    } else {
      lista.push(obj);
    }

    localStorage.setItem(
      this.chave,
      JSON.stringify(lista)
    );
  }

  // DELETE: exclui uma pessoa física
  excluir(id) {

    const novaLista = this.listar().filter(
      (p) => p.id !== id
    );

    localStorage.setItem(
      this.chave,
      JSON.stringify(novaLista)
    );
  }
}
```

### 3.2. Recuperando os registros com listar()

O método `listar()` recupera as informações armazenadas na chave `pessoasFisicas`.

```javascript
listar() {
  try {
    const dados = localStorage.getItem(this.chave);

    return dados ? JSON.parse(dados) : [];

  } catch (e) {
    console.error("Erro ao ler PF:", e);
    return [];
  }
}
```

A instrução:

```javascript
localStorage.getItem(this.chave)
```

recupera o conteúdo armazenado no navegador.

Como o `localStorage` armazena strings, precisamos utilizar:

```javascript
JSON.parse(dados)
```

para transformar o texto JSON em um objeto JavaScript.

Caso não existam dados, o método retorna um array vazio.

O bloco `try/catch` permite tratar situações em que o conteúdo armazenado não seja um JSON válido.

:::info Objetos recuperados do localStorage

O método `JSON.parse()` recupera objetos JavaScript comuns.

Isso significa que os objetos retornados não são automaticamente instâncias das classes `PF`, `PJ` ou `Endereco`.

Por esse motivo, os componentes de listagem e visualização acessarão diretamente os atributos armazenados.

:::

### 3.3. Gerando identificadores com gerarId()

O método `gerarId()` cria uma string utilizada para identificar um registro.

```javascript
gerarId() {
  return (
    Date.now().toString(36) +
    Math.random().toString(36).substring(2, 9)
  );
}
```

A instrução `Date.now()` retorna a quantidade de milissegundos decorridos desde 1º de janeiro de 1970.

O método `toString(36)` transforma esse número em uma representação alfanumérica.

Já `Math.random()` produz um número pseudoaleatório, utilizado para complementar o identificador.

A combinação dessas informações reduz a possibilidade de repetição dos identificadores em nosso protótipo.

:::warning Atenção

Esse método é adequado como mecanismo simples de identificação para a atividade didática, mas não garante unicidade absoluta.

Em aplicações reais, a estratégia de geração de identificadores deve considerar os requisitos de segurança, concorrência e integridade dos dados.

:::

### 3.4. Convertendo objetos com toPlain()

No capítulo anterior, utilizamos classes para representar pessoas físicas e seus atributos.

Por exemplo, uma pessoa física pode conter objetos associados:

```text
PF
├── nome
├── email
├── cpf
├── Endereco
├── Telefone[]
└── Titulo
```

Entretanto, ao armazenar essas informações, precisamos representar os dados em uma estrutura compatível com JSON.

O método `toPlain()` realiza essa conversão.

Observe:

```javascript
const end = pf.getEndereco?.();
const titulo = pf.getTitulo?.();
const telefones = pf.getTelefones?.() || [];
```

Essas instruções recuperam os objetos associados à pessoa física.

O operador `?.` é conhecido como **encadeamento opcional** (*optional chaining*).

Ele permite acessar um método somente quando a referência correspondente está disponível.

Em seguida, os dados são organizados em um objeto simples.

Por exemplo:

```javascript
endereco: end
  ? {
      cep: end.getCep?.(),
      logradouro: end.getLogradouro?.(),
      bairro: end.getBairro?.(),
      cidade: end.getCidade?.(),
      uf: end.getUf?.(),
      regiao: end.getRegiao?.(),
    }
  : {},
```

Observe que não estamos armazenando uma instância da classe `Endereco`.

Estamos armazenando um objeto que contém os valores necessários para representar o endereço.

Esse procedimento é importante porque o JSON não preserva os métodos das classes.

### 3.5. Armazenando registros com salvar()

O método `salvar()` representa a operação **Create** do CRUD.

```javascript
salvar(pf) {

  const lista = this.listar();
  const obj = this.toPlain(pf);

  if (!obj.id) {
    obj.id = this.gerarId();
  }

  lista.push(obj);

  localStorage.setItem(
    this.chave,
    JSON.stringify(lista)
  );

  return obj;
}
```

O procedimento é realizado em etapas:

1. Recuperar os registros existentes;
2. Converter a pessoa física em objeto simples;
3. Garantir que o novo registro possua um identificador;
4. Adicionar o objeto ao array;
5. Atualizar os dados armazenados no navegador.

Observe que o método utiliza:

```javascript
lista.push(obj);
```

Essa instrução adiciona um novo elemento ao final do array.

Depois, utilizamos:

```javascript
localStorage.setItem(
  this.chave,
  JSON.stringify(lista)
);
```

para armazenar a lista atualizada.

### 3.6. Atualizando registros com atualizar()

O método `atualizar()` representa a operação **Update** do CRUD.

Ele recebe dois parâmetros:

```javascript
atualizar(id, novoPF)
```

O primeiro parâmetro identifica o registro que deverá ser atualizado.

O segundo contém as novas informações da pessoa física.

Observe:

```javascript
const idx = lista.findIndex(
  (p) => p.id === id
);
```

O método `findIndex()` percorre o array e retorna o índice do primeiro elemento que satisfaz a condição informada.

Caso o registro seja encontrado, seu índice será maior ou igual a zero.

```javascript
if (idx >= 0) {
  lista[idx] = obj;
} else {
  lista.push(obj);
}
```

Na implementação utilizada, quando o identificador é encontrado, o objeto existente é substituído.

Caso contrário, o método adiciona um novo objeto à lista.

Esse comportamento é conhecido como **upsert**, pois combina atualização e inserção.

:::warning Observe o comportamento

Embora o método se chame `atualizar()`, a implementação também permite inserir um registro quando o identificador não é encontrado.

Em sistemas que exigem atualização estrita, seria possível lançar um erro caso o registro não existisse.

Neste capítulo, manteremos o comportamento da implementação utilizada no projeto.

:::

### 3.7. Excluindo registros com excluir()

O método `excluir()` representa a operação **Delete** do CRUD.

```javascript
excluir(id) {

  const novaLista = this.listar().filter(
    (p) => p.id !== id
  );

  localStorage.setItem(
    this.chave,
    JSON.stringify(novaLista)
  );
}
```

O método `filter()` percorre o array e constrói um novo array contendo somente os elementos que satisfazem a condição.

Observe a expressão:

```javascript
p.id !== id
```

Ela indica que devemos manter todos os registros cujo identificador seja diferente daquele informado.

Assim, o registro correspondente ao `id` será removido do novo array.

Por fim, a lista resultante substitui os dados armazenados anteriormente.

## 2. Apresentando dados com o componente Table

Esse componente permite apresentar coleções de objetos em uma estrutura de linhas e colunas.

- **Fonte de dados:** array contendo os objetos que serão apresentados;
- **Definição das colunas:** configuração que indica quais atributos deverão aparecer na interface.

```javascript
const pessoas = [
```

```jsx
const colunas = [
```

A propriedade `rowKey` indica qual atributo deverá ser utilizado para identificar cada linha.

## 6. Implementando o filtro por nome

Depois de recuperar os registros, precisamos selecionar aqueles que correspondem ao texto informado pelo usuário.

Para isso, utilizamos:

```javascript
const filtrados = lista.filter((p) =>
  p.nome?.toLowerCase().includes(filtroNome.toLowerCase())
);
```

Essa instrução combina três recursos do JavaScript:

- `filter()`;
- `toLowerCase()`;
- `includes()`.

### 6.1. O método filter()

O método `filter()` percorre um array e retorna um novo array contendo somente os elementos que satisfazem uma condição.

Por exemplo:

```javascript
const nomes = [
  "Ana Silva",
  "Carlos Souza",
  "Mariana Costa"
];

const resultado = nomes.filter(
  (nome) => nome.includes("Ana")
);
```

Nesse exemplo, o resultado será:

```javascript
["Ana Silva"]
```

### 6.2. O método includes()

O método `includes()` verifica se uma string contém determinado texto.

Por exemplo:

```javascript
"Ana Silva".includes("Ana"); // true

"Ana Silva".includes("João"); // false
```

Em nosso componente, o método é utilizado para verificar se o nome de uma pessoa contém o texto informado no filtro.

### 6.3. O método toLowerCase()

O método `toLowerCase()` transforma os caracteres de uma string em letras minúsculas.

Isso permite realizar uma pesquisa sem diferenciar letras maiúsculas e minúsculas.

Por exemplo:

```javascript
"ANA SILVA".toLowerCase();
```

O resultado será:

```text
ana silva
```

Assim, uma pesquisa por `"ana"` poderá encontrar registros como `"Ana Silva"` ou `"ANA SILVA"`.

:::tip Pesquisa dinâmica

O filtro será atualizado conforme o usuário digitar no campo de pesquisa.

Não será necessário pressionar um botão para executar a filtragem, pois utilizaremos o `useEffect()` para acompanhar as alterações no estado.

:::

## 3. Localizando um registro com o método find()

Na Parte 2, implementamos o método `listar()` nos DAOs.

Esse método retorna um array contendo os registros armazenados.

Entretanto, na visualização detalhada, não queremos apresentar todos os registros.

Precisamos localizar apenas a pessoa correspondente ao identificador recebido pela URL.

Para isso, utilizaremos o método `find()`.

Considere:

```javascript id="w9q4cr"
const pessoas = [
  {
    id: "abc123",
    nome: "Ana Silva"
  },
  {
    id: "def456",
    nome: "Carlos Souza"
  },
  {
    id: "ghi789",
    nome: "Mariana Costa"
  }
];
```

Para localizar Carlos, podemos utilizar:

```javascript id="r7j2vn"
const pessoa = pessoas.find(
  (p) => p.id === "def456"
);
```

O resultado será:

```javascript id="b3f8sm"
{
  id: "def456",
  nome: "Carlos Souza"
}
```

O método `find()` percorre o array e retorna o **primeiro elemento que satisfaz a condição informada**.

Caso nenhum elemento seja encontrado, o resultado será `undefined`.

### 3.1. Diferença entre find() e filter()

Na Parte 3, utilizamos o método `filter()` para implementar a pesquisa por nome.

Agora, utilizaremos `find()` para localizar um registro específico.

| Método | Retorno | Utilização |
|---|---|---|
| `filter()` | Array de elementos encontrados | Filtrar uma lista |
| `find()` | Primeiro elemento encontrado ou `undefined` | Localizar um registro |

Observe:

```javascript id="z2r9va"
const encontrados = pessoas.filter(
  (p) => p.nome.includes("Silva")
);
```

O resultado será um array.

Já:

```javascript id="a6f3wu"
const encontrada = pessoas.find(
  (p) => p.id === "abc123"
);
```

retornará diretamente o objeto correspondente.

:::info Escolhendo o método adequado

Quando precisamos recuperar vários registros, `filter()` costuma ser apropriado.

Quando precisamos localizar apenas um objeto, `find()` representa melhor a intenção da operação.

:::

```jsx title="src/components/visualizapessoa/VisualizaPessoa.jsx" id="e8n2vc"
import React, { useEffect, useState } from "react";

import {
  Card,
  Descriptions,
  Button
} from "antd";

import {
  useParams,
  useNavigate
} from "react-router-dom";

import PFDAO from "../../objetos/dao/PFDAOLocal.mjs";
import PJDAO from "../../objetos/dao/PJDAOLocal.mjs";

export default function VisualizaPessoa() {

  const { tipo, id } = useParams();

  const navigate = useNavigate();

  const [pessoa, setPessoa] = useState(null);

  useEffect(() => {

    const dao = tipo === "PF"
      ? new PFDAO()
      : new PJDAO();

    const lista = dao.listar();

    // Busca o registro pelo identificador
    const encontrada = lista.find(
      (p) => p.id === id
    );

    if (encontrada) {
      setPessoa(encontrada);
    }

  }, [tipo, id]);

  // Apresenta mensagem quando não encontra o cadastro
  if (!pessoa) {

    return (
      <div
        style={{
          textAlign: "center",
          marginTop: 40
        }}
      >

        <h3>Nenhuma pessoa encontrada.</h3>

        <Button
          type="primary"
          onClick={() => navigate("/listar")}
        >
          Voltar à lista
        </Button>

      </div>
    );
  }

  return (
    <div
      style={{
        maxWidth: 800,
        margin: "24px auto",
        background: "#fff",
        padding: 24,
        borderRadius: 8,
        boxShadow: "0 2px 8px rgba(0,0,0,0.05)",
      }}
    >

      <Card
        title={`Detalhes da ${
          tipo === "PF"
            ? "Pessoa Física"
            : "Pessoa Jurídica"
        }`}
        bordered={false}
      >

        <Descriptions
          bordered
          column={1}
        >

          <Descriptions.Item label="Nome">
            {pessoa.nome}
          </Descriptions.Item>

          <Descriptions.Item label="E-mail">
            {pessoa.email}
          </Descriptions.Item>

          {/* Documento principal */}

          {tipo === "PF" ? (

            <Descriptions.Item label="CPF">
              {pessoa.cpf}
            </Descriptions.Item>

          ) : (

            <Descriptions.Item label="CNPJ">
              {pessoa.cnpj}
            </Descriptions.Item>

          )}

          {/* Endereço */}

          <Descriptions.Item label="Endereço">

            {pessoa.endereco?.logradouro},{" "}
            {pessoa.endereco?.bairro} -{" "}
            {pessoa.endereco?.cidade}/
            {pessoa.endereco?.uf}

            <br />

            CEP: {pessoa.endereco?.cep}
            {" | "}
            Região: {pessoa.endereco?.regiao}

          </Descriptions.Item>

          {/* Telefones */}

          <Descriptions.Item label="Telefones">

            {pessoa.telefones?.length > 0
              ? pessoa.telefones
                  .map(
                    (t) => `(${t.ddd}) ${t.numero}`
                  )
                  .join(" | ")
              : "Não informado"}

          </Descriptions.Item>

          {/* Campos específicos de PF e PJ */}

          {tipo === "PF" ? (

            <>

              <Descriptions.Item
                label="Título Eleitoral"
              >

                {pessoa.titulo?.numero
                  ? `Nº ${pessoa.titulo.numero} - Zona ${pessoa.titulo.zona} / Seção ${pessoa.titulo.secao}`
                  : "Não informado"}

              </Descriptions.Item>

            </>

          ) : (

            <>

              <Descriptions.Item
                label="Inscrição Estadual"
              >

                {pessoa.ie?.numero
                  ? `Nº ${pessoa.ie.numero} - ${pessoa.ie.estado} (${pessoa.ie.dataRegistro})`
                  : "Não informado"}

              </Descriptions.Item>

            </>

          )}

        </Descriptions>

        {/* Botões de navegação */}

        <div
          style={{
            textAlign: "center",
            marginTop: 24
          }}
        >

          <Button
            type="primary"
            onClick={() =>
              navigate(`/editar/${tipo}/${pessoa.id}`)
            }
            style={{ marginRight: 12 }}
          >
            Editar
          </Button>

          <Button
            onClick={() => navigate("/listar")}
          >
            Voltar
          </Button>

        </div>

      </Card>

    </div>
  );
}
```

A implementação mantém a estrutura do componente funcional utilizado no projeto original.

```jsx id="c5y2xm"
</Descriptions.Item>
```

Nesse caso, apresentaremos as informações associadas à inscrição estadual.

Observe que o componente acessa diretamente os atributos do objeto recuperado do DAO.

Isso é possível porque o método `listar()` retorna objetos JavaScript simples, recuperados por meio de `JSON.parse()`.

## 10. Apresentando objetos compostos

Além dos atributos específicos, precisamos apresentar informações que estão armazenadas em objetos associados.

Esse é o caso do endereço e dos telefones.

### 10.1. Endereço

O endereço é armazenado como um objeto associado à pessoa.

Por exemplo:

```json id="w3n7qa"
{
  "endereco": {
    "cep": "70000000",
    "logradouro": "Rua Exemplo",
    "bairro": "Centro",
    "cidade": "Brasília",
    "uf": "DF",
    "regiao": "Centro-Oeste"
  }
}
```

Para apresentar essas informações, utilizamos:

```jsx id="s8k2fr"
<Descriptions.Item label="Endereço">

  {pessoa.endereco?.logradouro},{" "}
  {pessoa.endereco?.bairro} -{" "}
  {pessoa.endereco?.cidade}/
  {pessoa.endereco?.uf}

  <br />

  CEP: {pessoa.endereco?.cep}
  {" | "}
  Região: {pessoa.endereco?.regiao}

</Descriptions.Item>
```

Observe que utilizamos o operador `?.` para acessar os atributos do endereço.

Essa abordagem evita erros quando o objeto `endereco` não está disponível.

### 10.2. Telefones

Uma pessoa pode possuir vários telefones cadastrados.

Por isso, os telefones são armazenados em um array.

Por exemplo:

```json id="x6p9vt"
{
  "telefones": [
    {
      "ddd": "61",
      "numero": "999999999"
    },
    {
      "ddd": "61",
      "numero": "33333333"
    }
  ]
}
```

Para apresentar essas informações, utilizamos:

```jsx id="a7w4qp"
{pessoa.telefones?.length > 0
  ? pessoa.telefones
      .map((t) => `(${t.ddd}) ${t.numero}`)
      .join(" | ")
  : "Não informado"}
```

Essa expressão combina dois métodos importantes do JavaScript:

- `map()`;
- `join()`.

O método `map()` percorre o array e transforma cada telefone em uma string formatada.

Por exemplo:

```javascript id="k2r5yd"
["(61) 999999999", "(61) 33333333"]
```

Em seguida, `join(" | ")` combina os elementos em uma única string.

O resultado será:

```text id="t4n8vm"
(61) 999999999 | (61) 33333333
```

:::info Transformação de arrays

O método `map()` não modifica diretamente os objetos originais.

Ele produz um novo array contendo os valores resultantes da transformação aplicada a cada elemento.

Já `join()` transforma os elementos do array em uma única string, utilizando o separador informado.

:::

## 1. Reutilizando o formulário para diferentes operações

Uma das vantagens da componentização em React é a possibilidade de reutilizar a mesma interface em diferentes situações.

Considere o formulário de cadastro desenvolvido anteriormente.

Ele já possui os campos necessários para representar pessoas físicas e jurídicas.

Se criássemos outro componente exclusivamente para edição, precisaríamos repetir grande parte dessa estrutura.

Isso aumentaria a quantidade de código e dificultaria a manutenção.

Por exemplo, se futuramente adicionássemos um novo atributo à classe `Endereco`, seria necessário atualizar dois formulários diferentes.

Em vez disso, utilizaremos um único componente:

```text id="5h4vkn"
PessoaFormOO.jsx
       │
       ├── Modo Cadastro
       │      │
       │      └── dao.salvar()
       │
       └── Modo Edição
              │
              └── dao.atualizar()
```

O componente identificará o modo de funcionamento por meio dos parâmetros da URL.

---

## 2. Identificando o modo de edição

Na Parte 1, definimos duas rotas que utilizam o mesmo formulário:

```jsx id="g7q3km"
<Route
  path="cadastrar"
  element={<PessoaForm />}
/>

<Route
  path="editar/:tipo/:id"
  element={<PessoaForm />}
/>
```

Observe que ambas apresentam o mesmo componente React.

A diferença está na URL.

No cadastro, utilizaremos:

```text id="r4v8pq"
/cadastrar
```

Na edição, utilizaremos uma URL como:

```text id="k9m2fs"
/editar/PF/abc123
```

O endereço de edição contém dois parâmetros:

| Parâmetro | Finalidade |
|---|---|
| `tipo` | Identificar PF ou PJ |
| `id` | Identificar o registro |

Para recuperar essas informações, utilizaremos o hook `useParams()`.

```jsx id="t6n3cw"
const { tipo: tipoParam, id } = useParams();
```

Observe a expressão:

```javascript id="y2f8qh"
tipo: tipoParam
```

Ela permite atribuir um nome diferente à variável recuperada.

Assim, o parâmetro `tipo` da URL será armazenado na variável `tipoParam`.

Essa diferenciação é importante porque nosso formulário já possui uma variável de estado chamada `tipo`.

---

## 3. Controlando o modo de funcionamento

Além de recuperar os parâmetros da URL, precisamos identificar se o formulário está sendo utilizado para edição.

Para isso, utilizaremos:

```jsx id="b5q9wr"
const [editando, setEditando] = useState(false);
```

Inicialmente, o valor será `false`.

Isso significa que o formulário será apresentado no modo de cadastro.

Quando a aplicação identificar uma URL de edição, modificaremos esse estado:

```javascript id="p3k7vy"
setEditando(true);
```

O valor de `editando` será utilizado em diferentes situações.

Por exemplo:

| Situação | `editando` | Comportamento |
|---|---|---|
| Cadastro | `false` | Criar novo registro |
| Edição | `true` | Atualizar registro existente |

Também utilizaremos esse estado para modificar o título do formulário e o texto do botão principal.

## 4. Preparando o formulário para carregar dados existentes

Quando o usuário acessa a edição de um registro, precisamos recuperar suas informações.

Para isso, utilizaremos os DAOs desenvolvidos anteriormente.

O procedimento será:

```text id="n8x4ps"
Usuário seleciona Editar
            │
            ▼
 /editar/:tipo/:id
            │
            ▼
       useParams()
            │
            ▼
      Identifica o DAO
            │
            ▼
        dao.listar()
            │
            ▼
    Localiza o registro
            │
            ▼
  Converte os dados para
  os campos do formulário
            │
            ▼
    form.setFieldsValue()
            │
            ▼
    Formulário preenchido
```

A etapa de preenchimento utilizará o método `setFieldsValue()`, disponibilizado pelo Ant Design.

Esse método permite atribuir valores aos campos de um formulário controlado pelo componente `Form`.

Por exemplo:

```jsx id="z4m7qc"
form.setFieldsValue({
  nome: "Ana Silva",
  email: "ana@email.com",
  cpf: "11111111111"
});
```

Após a execução, os campos correspondentes serão preenchidos automaticamente.

:::tip Formulários controlados pelo Ant Design

O Ant Design disponibiliza métodos para recuperar, atribuir, validar e limpar valores de formulários.

Nesta etapa, utilizaremos principalmente:

- `Form.useForm()`;
- `setFieldsValue()`;
- `getFieldsValue()`;
- `resetFields()`.

Esses recursos permitem manipular os dados do formulário sem controlar individualmente o estado de cada campo.

:::

## 5. Modificando o componente PessoaFormOO

**Arquivo: `src/components/cadastrapessoa/PessoaFormOO.jsx` — MODIFICADO**

Nesta etapa, substituiremos o conteúdo do componente pelo código completo apresentado a seguir.

A implementação mantém a estrutura do formulário desenvolvido anteriormente, incluindo os componentes auxiliares e as classes de domínio.

A principal evolução será a incorporação dos recursos necessários para edição.

### 5.1. Código completo do arquivo

```jsx title="src/components/cadastrapessoa/PessoaFormOO.jsx" id="f8n2vq"
import React, { useState, useEffect } from "react";

import {
  Form,
  Input,
  Button,
  Radio,
  message
} from "antd";

import {
  useParams,
  useNavigate
} from "react-router-dom";

import dayjs from "dayjs";

// Componentes auxiliares
import EnderecoForm from "./EnderecoFormEX.jsx";
import TelefoneList from "./TelefoneListOO.jsx";
import PFForm from "./PFForm.jsx";
import PJForm from "./PJForm.jsx";

// DAOs
import PFDAO from "../../objetos/dao/PFDAOLocal.mjs";
import PJDAO from "../../objetos/dao/PJDAOLocal.mjs";

// Classes de domínio
import PF from "../../objetos/pessoas/PF.mjs";
import PJ from "../../objetos/pessoas/PJ.mjs";
import Endereco from "../../objetos/pessoas/Endereco.mjs";
import Telefone from "../../objetos/pessoas/Telefone.mjs";
import Titulo from "../../objetos/pessoas/Titulo.mjs";
import IE from "../../objetos/pessoas/IE.mjs";

export default function PessoaFormOO() {

  const [tipo, setTipo] = useState("PF");

  const [editando, setEditando] = useState(false);

  const [form] = Form.useForm();

  const navigate = useNavigate();

  const {
    tipo: tipoParam,
    id
  } = useParams();

  const pfDAO = new PFDAO();
  const pjDAO = new PJDAO();

  // =========================================
  // CARREGAMENTO DOS DADOS NO MODO DE EDIÇÃO
  // =========================================

  useEffect(() => {

    if (id && tipoParam) {

      setEditando(true);
      setTipo(tipoParam);

      const dao = tipoParam === "PF"
        ? pfDAO
        : pjDAO;

      const lista = dao.listar();

      const pessoa = lista.find(
        (p) => p.id === id
      );

      if (pessoa) {

        window.scrollTo({
          top: 0,
          behavior: "smooth"
        });

        const valores = {
          tipo: tipoParam,
          nome: pessoa.nome,
          email: pessoa.email,
          endereco: pessoa.endereco || {},
          telefones: pessoa.telefones || [],
        };

        if (tipoParam === "PF") {

          valores.cpf = pessoa.cpf;

          valores.titulo = pessoa.titulo || {
            numero: "",
            zona: "",
            secao: ""
          };

        } else {

          const ieObj = pessoa.ie || {};

          valores.cnpj = pessoa.cnpj;

          valores.ie = {
            numero: ieObj.numero || "",
            estado: ieObj.estado || "",
            dataRegistro: ieObj.dataRegistro
              ? dayjs(ieObj.dataRegistro)
              : null,
          };

        }

        form.setFieldsValue(valores);

      } else {

        message.error("Pessoa não encontrada!");

        navigate("/listar");

      }

    }

  }, [id, tipoParam]);

  // =========================================
  // ALTERAÇÃO DO TIPO DE PESSOA
  // =========================================

  function onChangeTipo(e) {

    const novoTipo = e.target.value;

    setTipo(novoTipo);

    const valoresAtuais = form.getFieldsValue();

    form.resetFields();

    form.setFieldsValue({
      ...valoresAtuais,
      tipo: novoTipo,
    });

  }

  // =========================================
  // SALVAR OU ATUALIZAR O REGISTRO
  // =========================================

  async function onFinish(values) {

    try {

      let pessoa;

      const endVals = values.endereco || {};

      // Construção do objeto Endereco
      const end = new Endereco();

      end.setCep(endVals.cep);
      end.setLogradouro(endVals.logradouro);
      end.setBairro(endVals.bairro);
      end.setCidade(endVals.cidade);
      end.setUf(endVals.uf);
      end.setRegiao(endVals.regiao);

      // =====================================
      // PESSOA FÍSICA
      // =====================================

      if (values.tipo === "PF") {

        const pf = new PF();

        pf.setNome(values.nome);
        pf.setEmail(values.email);
        pf.setCPF(values.cpf);
        pf.setEndereco(end);

        // Título eleitoral
        if (values.titulo) {

          const t = new Titulo();

          t.setNumero(values.titulo.numero);
          t.setZona(values.titulo.zona);
          t.setSecao(values.titulo.secao);

          pf.setTitulo(t);

        }

        // Telefones
        if (values.telefones?.length > 0) {

          values.telefones.forEach((tel) => {

            const fone = new Telefone();

            fone.setDdd(tel.ddd);
            fone.setNumero(tel.numero);

            pf.addTelefone(fone);

          });

        }

        pessoa = pf;

      } else {

        // ===================================
        // PESSOA JURÍDICA
        // ===================================

        const pj = new PJ();

        pj.setNome(values.nome);
        pj.setEmail(values.email);
        pj.setCNPJ(values.cnpj);
        pj.setEndereco(end);

        // Inscrição Estadual
        if (values.ie) {

          const ie = new IE();

          ie.setNumero(values.ie.numero);
          ie.setEstado(values.ie.estado);

          // Converte dayjs para string
          const dr = values.ie.dataRegistro;

          const dataRegistro =
            dr &&
            typeof dr === "object" &&
            typeof dr.format === "function"
              ? dr.format("YYYY-MM-DD")
              : dr || "";

          ie.setDataRegistro(dataRegistro);

          pj.setIE(ie);

        }

        // Telefones
        if (values.telefones?.length > 0) {

          values.telefones.forEach((tel) => {

            const fone = new Telefone();

            fone.setDdd(tel.ddd);
            fone.setNumero(tel.numero);

            pj.addTelefone(fone);

          });

        }

        pessoa = pj;

      }

      // =====================================
      // PERSISTÊNCIA: CADASTRO OU EDIÇÃO
      // =====================================

      const dao = tipo === "PF"
        ? pfDAO
        : pjDAO;

      if (editando && id) {

        dao.atualizar(id, pessoa);

        message.success(
          "Registro atualizado com sucesso!"
        );

      } else {

        dao.salvar(pessoa);

        message.success(
          "Registro criado com sucesso!"
        );

      }

      form.resetFields();

      setTimeout(
        () => navigate("/listar"),
        600
      );

    } catch (erro) {

      console.error(
        "Erro ao salvar:",
        erro
      );

      message.error(
        "Erro ao salvar registro: " + erro.message
      );

    }

  }

  // =========================================
  // APRESENTAÇÃO DO FORMULÁRIO
  // =========================================

  return (

    <div
      className="main-scroll"
      style={{
        overflowY: "auto",
        overflowX: "hidden",
        height: "100vh",
        background: "#f9f9f9",
      }}
    >

      <div
        className="form-container"
        style={{
          maxWidth: 800,
          margin: "24px auto",
          background: "#fff",
          padding: 24,
          borderRadius: 8,
          boxShadow: "0 2px 8px rgba(0,0,0,0.05)",
        }}
      >

        <h2
          style={{
            textAlign: "center",
            marginBottom: 20
          }}
        >

          {editando
            ? `Editar ${
                tipo === "PF"
                  ? "Pessoa Física"
                  : "Pessoa Jurídica"
              }`
            : `Cadastro de ${
                tipo === "PF"
                  ? "Pessoa Física"
                  : "Pessoa Jurídica"
              }`}

        </h2>

        <Form
          layout="vertical"
          form={form}
          onFinish={onFinish}
          scrollToFirstError
        >

          {/* Tipo de Pessoa */}

          <Form.Item
            label="Tipo de Pessoa"
            name="tipo"
            initialValue="PF"
            style={{ marginBottom: 10 }}
          >
```

A principal diferença entre cadastro e edição aparece no momento da persistência.

```jsx title="src/routes/AppRoutes.jsx"
          element={<ListaPessoas />}
        />

        {/* Visualização */}

        <Route
          path="visualizar/:tipo/:id"
          element={<VisualizaPessoa />}
        />

        {/* Edição */}

        <Route
          path="editar/:tipo/:id"
          element={<PessoaForm />}
        />

      </Route>

    </Routes>

  );

}

export default AppRoutes;
```

Observe que as rotas de cadastro e edição utilizam o mesmo componente:

```jsx
<Route
  path="cadastrar"
  element={<PessoaForm />}
/>

<Route
  path="editar/:tipo/:id"
  element={<PessoaForm />}
/>
```

Essa configuração permite reutilizar o formulário desenvolvido na Parte 5.

O próprio componente identifica se está no modo de cadastro ou edição, conforme os parâmetros recebidos.

## 3. Compreendendo o papel do MainLayout

O arquivo `MainLayout.jsx` foi criado na Parte 1.

Ele estabelece a estrutura visual compartilhada pelas diferentes telas.

Em nosso projeto, utilizamos os componentes de layout e navegação do Ant Design.

A principal característica dessa organização é permitir que o menu permaneça disponível enquanto o conteúdo central é alterado.

Para isso, utilizamos o componente `Outlet`, disponibilizado pelo React Router.

Observe:

```jsx
import { Outlet } from "react-router-dom";
```

No ponto em que o componente `Outlet` é apresentado, o React Router renderiza o componente correspondente à rota atual.

Por exemplo:

```text
MainLayout
    │
    ├── Menu de navegação
    │
    └── Outlet
          │
          ├── PessoaFormOO
          ├── ListaPessoas
          └── VisualizaPessoa
```

Quando o usuário acessa `/cadastrar`, o `Outlet` apresenta o formulário.

Quando acessa `/listar`, apresenta a tabela.

Quando acessa `/visualizar/PF/abc123`, apresenta os detalhes do registro identificado.

:::tip Reutilização de layouts

A utilização de um layout compartilhado evita repetir o menu e outros elementos estruturais em cada componente.

Também facilita futuras modificações na aparência da aplicação.

:::

## 6. Ativando a navegação no App.jsx

**Arquivo: `src/App.jsx` — MODIFICADO**

Agora, realizaremos a última modificação necessária para integrar a aplicação.

Até o capítulo anterior, o `App.jsx` apresentava diretamente o componente de cadastro.

Entretanto, nossa aplicação agora possui diferentes telas.

Por isso, utilizaremos o `BrowserRouter` para disponibilizar o contexto de navegação.

### 6.1. Código completo do App.jsx

Substitua integralmente o conteúdo do arquivo `App.jsx` pelo código abaixo.

```jsx title="src/App.jsx"
import {
  BrowserRouter as Router
} from "react-router-dom";

import AppRoutes from "./routes/AppRoutes.jsx";

function App() {

  return (

    <Router>

      <AppRoutes />

    </Router>

  );

}

export default App;
```

Observe que o código é relativamente pequeno.

Isso acontece porque as responsabilidades da aplicação estão distribuídas entre diferentes componentes.

O `App.jsx` não precisa conhecer os detalhes do formulário, da listagem ou da persistência.

Sua responsabilidade é inicializar o contexto de navegação e apresentar o componente que organiza as rotas.

### 6.2. O papel do BrowserRouter

O componente `BrowserRouter` permite que a aplicação utilize a URL do navegador para controlar a navegação.

Observe:

```jsx
<Router>

  <AppRoutes />

</Router>
```

Todos os componentes apresentados dentro de `Router` poderão utilizar os recursos de navegação disponibilizados pelo React Router.

Isso inclui os hooks:

```javascript
useNavigate()
useParams()
```

Esses hooks foram utilizados nas etapas anteriores.

Agora, com a ativação do `BrowserRouter`, poderão funcionar dentro do contexto de navegação da aplicação.

:::warning Atenção

O `BrowserRouter` deverá envolver o conjunto de rotas da aplicação.

Evite criar outro `BrowserRouter` dentro dos componentes `ListaPessoas`, `VisualizaPessoa` ou `PessoaFormOO`.

Nesta implementação, utilizaremos apenas um contexto principal de navegação, definido no `App.jsx`.

:::

## 14. Compreendendo a arquitetura final

Com a integração concluída, nossa aplicação apresenta uma organização em camadas.

### 14.1. Camada de apresentação

Responsável pela interação com o usuário.

Inclui:

```text
PessoaFormOO.jsx
ListaPessoas.jsx
VisualizaPessoa.jsx
```

Esses componentes apresentam informações, recebem dados e respondem às ações do usuário.

### 14.2. Camada de navegação

Responsável pela organização das rotas e pela estrutura compartilhada da interface.

Inclui:

```text
App.jsx
AppRoutes.jsx
MainLayout.jsx
```

Essa camada determina qual componente será apresentado conforme a URL.

### 14.3. Camada de domínio

Responsável pela representação dos objetos da aplicação.

Inclui as classes:

```text
PF
PJ
Endereco
Telefone
Titulo
IE
```

Essas classes representam as entidades e seus atributos.

### 14.4. Camada de persistência

Responsável pelo armazenamento e pela recuperação dos registros.

Inclui:

```text
PFDAOLocal.mjs
PJDAOLocal.mjs
```

Esses DAOs utilizam o `localStorage` para executar as operações CRUD.

A organização final será:

```text
              USUÁRIO
                 │
                 ▼
        COMPONENTES REACT
                 │
                 ▼
          CLASSES DE DOMÍNIO
                 │
                 ▼
                DAOs
                 │
                 ▼
            localStorage
```

Observe que a aplicação utiliza diferentes recursos tecnológicos, mas mantém responsabilidades organizadas.

Essa separação facilitará a evolução do projeto nas próximas etapas.
