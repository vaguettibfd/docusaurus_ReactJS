# 📘 Bibliotecas de Componentes Externos

Nos capítulos anteriores, construímos e estilizamos nossa aplicação React
utilizando diferentes abordagens.

Inicialmente, utilizamos **CSS tradicional**, criando arquivos específicos para
definir a aparência dos componentes.

Depois, utilizamos **Tailwind CSS**, aplicando classes utilitárias diretamente
nos elementos JSX.

Agora conheceremos uma terceira possibilidade: utilizar **bibliotecas de
componentes externos**.

Essas bibliotecas disponibilizam componentes de interface prontos para serem
utilizados em aplicações React.

Alguns exemplos são:

- Material UI;
- Ant Design;
- React Bootstrap;
- PrimeReact.

Podemos representar essa evolução da seguinte maneira:

```text
CSS tradicional
      │
      ▼
Criamos nossos estilos
      │
      ▼
Componente + arquivo CSS


Tailwind
      │
      ▼
Utilizamos classes utilitárias
      │
      ▼
Componente + className


Biblioteca de componentes
      │
      ▼
Utilizamos componentes prontos
      │
      ▼
Componente React + Design System
```

:::info Biblioteca de componentes

Uma **biblioteca de componentes** disponibiliza elementos de interface
reutilizáveis que podem ser incorporados à aplicação.

Esses componentes normalmente já possuem características como:

- aparência visual;
- espaçamento;
- estados de interação;
- comportamentos;
- variações;
- padronização.

Assim, em vez de construirmos todos os elementos da interface a partir de
elementos HTML básicos, podemos utilizar componentes fornecidos pela
biblioteca.

:::

---

# Algumas bibliotecas disponíveis

Existem diferentes bibliotecas de componentes para React.

Entre elas:

| Biblioteca | Característica |
|---|---|
| Material UI | Biblioteca baseada nos princípios do Material Design |
| Ant Design | Design System com ampla variedade de componentes |
| React Bootstrap | Componentes Bootstrap implementados para React |
| PrimeReact | Biblioteca com diversos componentes de interface |

A escolha de uma biblioteca pode considerar diferentes fatores, como:

```text
Biblioteca
    │
    ├── componentes disponíveis
    ├── documentação
    ├── facilidade de utilização
    ├── compatibilidade com o projeto
    ├── manutenção
    └── adoção pela comunidade
```

:::tip Analisando bibliotecas

Ferramentas como **NPM Trends** podem ser utilizadas para comparar a evolução
de downloads de diferentes pacotes publicados no NPM.

Entretanto, quantidade de downloads não deve ser o único critério para a
escolha de uma biblioteca.

É importante analisar também as necessidades específicas do projeto.

:::

# Design System

Antes de começarmos a implementação, é importante compreender o conceito de
**Design System**.

Um Design System reúne padrões utilizados para manter consistência na
construção de interfaces.

Esses padrões podem envolver:

```text
Design System
     │
     ├── cores
     ├── tipografia
     ├── espaçamento
     ├── componentes
     ├── estados visuais
     └── padrões de interação
```

Quando utilizamos componentes pertencentes ao mesmo Design System, eles tendem
a compartilhar uma identidade visual comum.

Por exemplo:

```text
Input
Button
Card
Alert
Typography
      │
      └───────────────┐
                      ▼
               Design System
                      │
                      ▼
             Consistência visual
```

:::info

Uma das vantagens de uma biblioteca como o Ant Design é que não estamos
utilizando apenas componentes isolados.

Os componentes fazem parte de um **sistema visual consistente**.

:::

# Componente `InputText.jsx`

Agora começaremos a observar uma vantagem importante de utilizar componentes
prontos.

No capítulo anterior construímos o campo utilizando:

```jsx
<input>
```

e adicionamos manualmente diferentes classes Tailwind.

Agora utilizaremos:

```jsx
<Input />
```

do Ant Design.

Também utilizaremos:

```jsx
<Alert />
```

para apresentar a mensagem de validação.

## `InputText.jsx`

```jsx
import React, { useState } from "react";
import { Input, Alert } from "antd";

export default function InputText({ placeholder }) {

  const [valor, setValor] = useState("");
  const [erro, setErro] = useState(false);

  const handleChange = (e) => {

    const novoValor = e.target.value;

    setValor(novoValor);

    setErro(novoValor.trim() === "");
  };

  return (
    <div>

      <Input
        placeholder={placeholder}
        value={valor}
        onChange={handleChange}
        size="large"
        status={erro ? "error" : ""}
      />

      {erro && (
        <Alert
          message="O campo não pode ficar vazio."
          type="error"
          showIcon
          style={{ marginTop: 8 }}
        />
      )}

    </div>
  );
}
```

---

# Estado e biblioteca de componentes

É importante observar que os conceitos de React continuam funcionando
normalmente.

Temos:

```jsx
const [valor, setValor] = useState("");
const [erro, setErro] = useState(false);
```

e:

```jsx
const handleChange = (e) => {

  const novoValor = e.target.value;

  setValor(novoValor);

  setErro(novoValor.trim() === "");
};
```

Portanto:

```text
Usuário digita
      │
      ▼
onChange
      │
      ▼
handleChange()
      │
      ├── setValor()
      │
      └── setErro()
              │
              ▼
        nova renderização
```

A utilização do Ant Design **não substitui o state do React**.

O que muda é o componente visual utilizado para apresentar o campo.

    │   Input normal
    │
    └── true
           │
           ▼

           │

      Input com indicação

# Componente `Button.jsx`

Agora utilizaremos o botão fornecido pelo Ant Design.

Como já possuímos um componente chamado `Button`, utilizaremos um **alias** na
importação.

## `Button.jsx`

```jsx
import React, { useState } from "react";

import {
  Button as AntButton,
  message
} from "antd";

export default function Button({ valor }) {

  const [texto, setTexto] = useState(valor);

  const handleClick = () => {

    setTexto("Você clicou!");

    message.success(
      "Botão clicado com sucesso!"
    );
  };

  return (
    <AntButton
      type="primary"
      block
      size="large"
      onClick={handleClick}
    >
      {texto}
    </AntButton>
  );
}
```

# Componentes HTML e Ant Design

Também podemos comparar alguns elementos:

# Resumo

Neste capítulo conhecemos uma nova estratégia para construção de interfaces
React: a utilização de **bibliotecas de componentes externos**.

Utilizamos o **Ant Design** para reconstruir a aplicação de Login desenvolvida
nos capítulos anteriores.

Nossa evolução agora pode ser representada como:

```text
Estrutura do React
        │
        ▼
Componentes
        │
        ▼
Props
        │
        ▼
State
        │
        ▼
Eventos
        │
        ▼
CSS
        │
        ▼
Tailwind
        │
        ▼
Bibliotecas de Componentes
        │
        ▼
Ant Design
        │
        ▼
Design System
```

Com Ant Design utilizamos:

```text
Typography
Input
Input.Password
Alert
Button
message
Card
Space
```

Esses recursos fornecem componentes visuais e comportamentos prontos,
mantendo uma identidade visual consistente.

Ao mesmo tempo, continuamos utilizando os conceitos fundamentais do React:

```text
Componentes
     │
     ├── Props
     ├── State
     ├── Eventos
     ├── Renderização condicional
     └── Composição
```

Assim, uma biblioteca de componentes não substitui o React.

Ela fornece recursos de interface que podem ser **integrados aos componentes
da nossa aplicação**, reduzindo a necessidade de construir manualmente
elementos visuais recorrentes.
